# Аппаратная составляющая часов
Существует два основных типа компьютерных часов: старые, работавшие от электросети (50-60 Гц), и современные программируемые.

Устройство современных программируемых часов включает три компонента: кварцевый генератор (создает стабильный сигнал высокой частоты), регистр хранения (хранит заданное число) и счетчик (уменьшает это число с каждым импульсом генератора). При достижении счетчиком нуля генерируется прерывание процессора.

Режимы работы:
1. Однократный импульс: после обнуления счетчика выдается одно прерывание и часы останавливаются.
2. Прямоугольный импульс (периодический): после обнуления счетчик автоматически перезагружается из регистра хранения, создавая бесконечную серию прерываний (clock ticks).

Программируемые часы позволяют гибко настраивать интервалы прерываний через софт. Для сохранения времени при выключенном питании используются отдельные резервные часы с батарейкой (CMOS/RTC). При загрузке ОС считывает значение с этих часов и переводит его в системный формат - количество тактов, прошедших с определенной точки отсчета (эпохи). Для UNIX это 1 января 1970 года (UTC), для Windows - 1 января 1980 года. В дальнейшем системное время инкрементируется с каждым тактом часов.

# Программная составляющая часов
Драйвер часов выполняет следующие функции: ведение времени суток, предотвращение слишком долгой работы процессов, учет использования центрального процессора, обработка системного вызова alarm, предоставление сторожевых таймеров для ядра ОС и сбор статистической информации.

Для ведения времени суток (фактического времени) обычно используется счетчик тактов. Чтобы избежать переполнения 32-разрядного счетчика (которое при частоте 60 Гц наступает через 2 года), применяются три способа:

1. Использование 64-разрядного счетчика тактов.
2. Ведение времени в секундах (32 бита) с использованием вспомогательного счетчика для тактов внутри текущей секунды.
3. Подсчет тактов относительно времени загрузки системы. В этом случае текущее время вычисляется как сумма времени загрузки (взятого из резервных часов) и текущего значения счетчика тактов.

Вторая функция часов заключается в предотвращении излишне продолжительной работы процессов. При каждом запуске процесса планировщик запускает его счетчик кванта времени в тактах системных часов. При каждом прерывании драйвер часов уменьшает это значение на единицу. Когда оно достигает нуля, драйвер вызывает планировщик для переключения на другой процесс.

Третья функция - ведение учета использования центрального процессора. Это реализуется двумя способами:

- Точный способ: запуск второго независимого таймера при старте процесса. При остановке процесса значение таймера считывается для определения продолжительности работы. Значение таймера должно сохраняться и восстанавливаться при прерываниях.
- Простой способ: использование глобальной переменной с указателем на текущий процесс. При каждом такте часов значение поля времени в записи этого процесса увеличивается на единицу.

Проблема простого способа заключается в том, что процессу отводится полный такт, даже если из-за прерываний он не выполнил существенной работы. Строгий учет времени в условиях прерываний ресурсозатратен и применяется редко.

# Программируемые таймеры
Большинство компьютеров оборудованы вторыми программируемыми часами, которые могут быть настроены на выдачу таймерных прерываний с любыми нужными характеристиками. Для управления вводом-выводом используются два способа: прерывания и опросы. Прерывания обеспечивают минимальную задержку, но создают высокие издержки на современных процессорах из-за переключения контекста, влияния на конвейер, буфер TLB и кэш. Опросы позволяют избежать прерываний, но вносят задержку, составляющую в среднем половину интервала между опросами.

Программные таймеры выступают альтернативой, позволяющей избежать прерываний. При входе в ядро по любой причине перед возвратом в пользовательский режим проверяется фактическое время. Если время таймера истекло, выполняется запланированное событие без дополнительного перехода в режим ядра. После этого таймер перезапускается путем добавления времени ожидания к текущему значению часов.
